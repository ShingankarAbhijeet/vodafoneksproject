Phase 1
Foundation
Steps 1 – 4
1
OIDC Federation — Replace Static AWS Keys
Set up OpenID Connect trust between GitHub Actions and AWS. GitHub gets short-lived tokens per workflow run. Delete all static AWS keys from GitHub Secrets once done.
OIDC Trust Policy IAM Role (GitHub OIDC) Terraform GitHub Secrets
2
ECR — Container Registry Setup
Create ECR repos via Terraform — one per environment. Enable image immutability and tag scanning. Also configure ECR as an OCI registry to store Helm charts.
AWS ECR Immutable Tags OCI Helm Storage Terraform ECR Scanning
3
Dockerfile — Containerise the App
Write a multi-stage Dockerfile. Build stage compiles the app, final stage uses a distroless or slim base image. No dev dependencies, no secrets baked in, minimal attack surface.
Multi-Stage Build Distroless Base BuildKit .dockerignore
4
CI Workflow — Build, Scan, Sign, Push
Create ci.yml triggering on push and PR. Pipeline: lint → unit tests → SonarCloud quality gate → Docker build → Trivy scan (fail on CRITICAL) → Gitleaks secret scan → Cosign image signing → push to ECR tagged with git SHA.
SonarCloud Trivy Cosign Gitleaks Syft SBOM GitHub Actions
Phase 2
GitOps Core
Steps 5 – 8
5
Helm Chart — Package the Application
Create a Helm chart for your service inside the app repo. One base values.yaml and separate override files per environment (dev, qa, staging, prod). Push the chart to ECR OCI registry.
Helm Chart values-dev/qa/staging/prod.yaml ECR OCI Chart versioning
6
Namespace Structure — Env Isolation on Cluster
Create dev, qa and staging namespaces on the existing cluster via Terraform. Prod gets its own separate cluster later. Set resource quotas and default limits per namespace.
Namespaces: dev / qa / staging ResourceQuota LimitRange Terraform
7
ArgoCD — Install and Wire the GitOps Loop
Install ArgoCD via Helm (managed by Terraform). Set up App-of-Apps pattern — one root app per cluster that generates child apps per service/env. Configure GitHub OAuth SSO. First merge to develop should auto-sync a pod running in dev namespace.
ArgoCD App-of-Apps ApplicationSet GitHub OAuth ArgoCD RBAC
8
ArgoCD Image Updater + CD Flow dev → qa → staging
ArgoCD Image Updater watches ECR and auto-commits the new image tag to the GitOps repo — no manual CD trigger needed. Set up sequential promotion: auto-deploy to dev, then QA, then staging. Slack notification posted at each stage.
ArgoCD Image Updater Sync Waves Slack notify GitHub Actions cd.yml
Phase 3
Security Hardening
Steps 9 – 13
9
Kyverno — Admission Policies
Install Kyverno and enforce core policies cluster-wide: block :latest image tag, require signed images (Cosign), require resource limits, require liveness and readiness probes, enforce Pod Security Standards restricted profile, auto-generate NetworkPolicy per namespace.
Kyverno ClusterPolicy PSS Restricted Auto NetworkPolicy
10
Calico — Default-Deny Network Policy
Install Calico CNI and apply a default-deny GlobalNetworkPolicy across all namespaces. Only explicitly allowed traffic flows between services. This is the baseline for zero-trust networking inside the cluster.
Calico Default-Deny Policy GlobalNetworkPolicy Namespace isolation
11
Istio — Service Mesh + mTLS
Install Istio (istioctl or Helm). Enable mTLS strict mode across all namespaces — all pod-to-pod traffic is automatically encrypted. Add AuthorizationPolicy for zero-trust service auth. Configure Istio Gateway as the cluster ingress. Set up Kiali for live mesh visibility.
Istio mTLS Strict AuthorizationPolicy Kiali Istio Gateway
12
Falco — Runtime Threat Detection
Install Falco as a DaemonSet. Enable rules for: shell spawned inside container, privilege escalation, sensitive file reads, unexpected outbound connections. Install Falco Sidekick to route alerts to a dedicated Slack channel #alerts-security.
Falco Falco Sidekick Syscall rules Slack #alerts-security
13
Vault + External Secrets — Zero Static Secrets
Deploy HashiCorp Vault for dynamic secrets and PKI. Install External Secrets Operator to sync secrets from AWS Secrets Manager into Kubernetes Secrets automatically. No hardcoded secrets in manifests, Helm values, or environment variables.
HashiCorp Vault External Secrets Operator AWS Secrets Manager Dynamic secrets
Phase 4
Progressive Delivery & Prod
Steps 14 – 17
14
Argo Rollouts — Blue/Green and Canary
Install Argo Rollouts. Migrate staging deployments to blue/green strategy. Set up prod canary: start at 10% traffic, auto-promote using Prometheus error rate as the analysis metric. Auto-rollback if the metric threshold breaches.
Argo Rollouts Blue/Green (staging) Canary (prod) AnalysisTemplate Prometheus metric gate
15
Separate Prod EKS Cluster — via Terraform
Provision a dedicated production EKS cluster using the same Terragrunt module as dev/qa/staging but with prod-grade node sizing, multi-AZ topology spread, separate VPC, private subnets, and tighter IAM. Prod cluster is never shared with any other environment.
Separate EKS Cluster Private subnets Multi-AZ spread Terragrunt Karpenter
16
GitHub Environments — Manual Approval Gate to Prod
Configure a GitHub Environment named "production" with required reviewers. The prod CD workflow pauses here, sends a Slack notification with a direct approval link, and only proceeds after a reviewer approves in GitHub. This is the last human gate before prod.
GitHub Environments Required Reviewers Slack approval link cd-prod.yml
17
TLS Everywhere — cert-manager + ACM
Install cert-manager for in-cluster TLS certificate management. Use AWS ACM for ALB/Ingress TLS termination. All internal service-to-service traffic is covered by Istio mTLS (Step 11). No unencrypted traffic anywhere.
cert-manager AWS ACM ClusterIssuer ALB TLS
Phase 5
Observability
Steps 18 – 21
18
Metrics — Prometheus + Grafana
Install kube-prometheus-stack via Helm. Includes Prometheus, Grafana, and a full set of pre-built Kubernetes dashboards. Add app-level dashboards for your service. Enable Grafana SSO via GitHub. Set SLO dashboards for prod.
Prometheus Grafana kube-prometheus-stack SLO dashboards Kubecost
19
Logs — Loki + Promtail
Install Loki and Promtail via Helm. Promtail runs as a DaemonSet and ships all container logs to Loki. Grafana becomes the single pane of glass for both metrics and logs. No separate log management tool needed.
Loki Promtail Grafana log explorer Log retention policy
20
Traces — OpenTelemetry + Grafana Tempo
Deploy OpenTelemetry Collector as the vendor-neutral trace pipeline. Istio auto-instruments service-to-service calls. Traces ship to Grafana Tempo. Grafana links traces, logs, and metrics together — one click from a Grafana panel to the full trace.
OpenTelemetry Grafana Tempo Istio auto-instrument Trace-log correlation
21
Alerting — Alertmanager + PagerDuty
Configure Alertmanager routing: warning alerts go to Slack #alerts, critical prod alerts go to PagerDuty for on-call escalation. Set up HPA, VPA, and PodDisruptionBudget on all deployments. Alertmanager silences during planned maintenance windows.
Alertmanager PagerDuty (prod P1) Slack routing HPA + VPA + PDB
Phase 6
Final Hardening & Polish
Steps 22 – 26
22
Velero — Cluster Backup & Restore
Install Velero with S3 as the backup target. Schedule daily full cluster backups including PVCs, secrets, and configmaps. Test a restore in the staging cluster before trusting it for prod. Define an RTO/RPO target and document the restore runbook.
Velero S3 backup target Daily schedule Restore tested
23
Karpenter — Node Autoscaling
Replace the default Cluster Autoscaler with Karpenter. Define NodePools with right-sized instance families. Karpenter provisions exact-fit nodes in seconds and consolidates underutilised nodes automatically — significant cost reduction at scale.
Karpenter NodePool EC2NodeClass Spot + On-demand mix
24
Checkov — Terraform Security Scan in Infra CI
Add Checkov to the infra workflow so every Terraform PR is automatically scanned for misconfigurations (open security groups, public S3 buckets, missing encryption). Fails the plan job if HIGH severity issues are found. No human needs to remember to check.
Checkov Terraform scan infra-plan.yml SARIF report
25
Semantic Release + Conventional Commits
Enforce Conventional Commits via a commit-msg hook (commitlint). Wire Semantic Release to run on merge to master — it auto-bumps the version, tags the release, and generates a changelog. Helm chart version and image tag are driven by this automatically.
Semantic Release Conventional Commits commitlint Auto CHANGELOG
26
Nightly Security Re-Scan + Final Branch Rules
Add a scheduled GitHub Actions workflow that re-scans all ECR images nightly with Trivy — catches newly disclosed CVEs on images already in production. Finalise master branch protection: required PR, required CI pass, required SonarCloud quality gate, no direct push, no force push.
Nightly Trivy scan Branch protection (master) Required reviewers SonarCloud gate
